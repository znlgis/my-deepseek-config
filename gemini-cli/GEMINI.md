# GEMINI.md — Gemini CLI × DeepSeek 项目记忆

> Gemini CLI 的上下文记忆文件（在 `settings.json` 中通过 `contextFileName` 指定）。
> 项目根目录下的 `GEMINI.md` 会被 Gemini CLI 自动加载。完整通用规则见
> [`shared/RULES.md`](../shared/RULES.md)，本文件为精炼版 + Gemini CLI 专属约定。

## 模型分工（DeepSeek 双模型）

| 模型 | 用途 |
|------|------|
| `deepseek-reasoner`（Pro） | 规划、架构、根因分析、代码审查、重型实现 |
| `deepseek-chat`（Flash） | 探索、检索、简单编辑、通用问答、轻量任务 |

- **Flash 优先**：搜索 / 查找 / 小改动用 `deepseek-chat`（在 `.env` 中设为默认）。
- **Pro 升级**：Flash 力不从心时切到 `deepseek-reasoner`。
- 接入端点：`https://api.deepseek.com/v1`（OpenAI 兼容），API Key 通过 `.env` 注入，**切勿写入仓库**。

## 核心原则

1. **先辨意图再动手。**「解释 X」不是「改 X」。用户没明确要求时不动代码。
2. **最小改动，完整正确。**只改完成任务必需的代码，不动无关部分。
3. **先读后写。**不要凭记忆写代码——先打开真实文件验证假设。
4. **并行处理独立任务。**互不依赖的操作（读取 / 搜索 / 检索）一次性发起。
5. **未经请求不创建文件。**不主动创建 README、文档或任何新文件。
6. **语言跟随 OS。**中文 Windows 用中文回复，英文系统用英文。

## 多步任务纪律

≥2 步任务：先写有序待办清单 → 一次只做一项 → 完成即标记 → 范围变化时更新清单。

## 上下文与 Token 效率

- **引用路径，别贴整文件。**指向 `src/app.ts:42`，不要把整个文件塞进对话。
- **委派而非堆积。**大文件交由子代理读取，不要全灌入主上下文。
- **并行独立读取。**3+ 个互不依赖的文件一次全发起。
- **快变库先检索。**具体或高频变动的 API 不凭记忆写，先查官方文档。

## 反模式（严格禁止）

- ❌ 不建万能文件（`utils.ts`、`helpers.ts`、`service.ts`）
- ❌ 代码 / 注释中不用 emoji
- ❌ 不用 AI 填充词（"simply"、"obviously"、"clearly"等）
- ❌ 不留空 `catch` 块；不留被注释掉的死代码
- ❌ `@ts-ignore` / `@ts-expect-error` 必须附解释性注释

## 代码风格

- 优先 `const` 而非 `let`；用三元 / 提前返回代替重赋值。
- 避免 `else` ——用提前返回压平结构。
- 函数式方法（`map` / `filter` / `flatMap`）优先于 `for` 循环。
- 减少中间变量；避免不必要的解构（用 `obj.prop`）。
- 不用 `import * as` 通配导入；不用无必要的导入别名。
- 不提前提取只用一次的函数。

## 注释 + 证据纪律

- 注释解释 WHY 不解释 WHAT；不写 AI 模板注释。
- 完成前必须有可验证证据——测试 / build / lint / 调用方 grep 至少一项。
- 汇报发现时引用具体位置（`file:line`）。

## 提交前自检

1. 从头到尾复读每个改动文件。
2. `grep` 检查修改的函数 / 类型是否有调用方被破坏。
3. 有测试则运行；无测试则声明跳过。
4. 清理未用的导入 / 变量 / 参数。

## 常见陷阱

- **不要自己悄悄"修"不相关的东西。**只改任务范围内的代码。
- **不要基于猜测创建新文件。**除非任务明确要求，否则不动文件系统。
- **不要保留调试代码。**`console.log`、`TODO` 注释等提交前清理。
- **不要用"应该没问题"代替验证。**没跑过的断言都不算数。

## 工作流约定

1. 接到任务 → 先确认理解（有必要时提问）→ 制定计划（≥2 步先列 todo）→ 执行 → 自检 → 汇报。
2. 每个修改的文件重新通读一遍再提交。
3. 如果某个操作的产出可能很大（如 diff 超过 500 行），先告知范围再行动。
4. 遇到不确定的技术选型（库版本、API 用法），先查文档而非凭记忆。

## Skill 文件位置

Skill 文件位于 `.gemini/skills/` 目录下，Gemini CLI 会自动发现并加载。当前可用的 Skill：

- `code-review` — 多维代码审查，严重度分级
- `conventional-commits` — Conventional Commits 规范
- `security-review` — 安全审查清单
- `verification-before-completion` — 完成前强制验证

使用时直接用 `@skill-name` 语法触发对应 Skill。
