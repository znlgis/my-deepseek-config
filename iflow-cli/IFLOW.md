# IFLOW.md — iFlow CLI × DeepSeek 项目记忆

> iFlow CLI 的上下文记忆文件（`settings.json` 中 `contextFileName` 指定）。
> 放在项目根目录或 `~/.iflow/IFLOW.md`。
> 核心通用规则来自 [`shared/RULES.md`](../shared/RULES.md)，本文件聚焦 iFlow 专属约定与工作流。

## 模型分工（DeepSeek 双模型）

iFlow CLI 通过 OpenAI 兼容配置接入 DeepSeek：

| 档位 | 模型 ID | 定位 | 用途 |
| --- | --- | --- | --- |
| Pro | `deepseek-v4-pro` | 强推理 | 规划、架构、根因分析、代码审查、重型实现 |
| Flash | `deepseek-v4-flash` | 快速通用 | 探索、检索、简单编辑、通用问答（默认） |

- **Flash 优先**：搜索 / 查找 / 小改动先用 Flash。
- **Pro 升级**：Flash 力不从心时，携带完整上下文升至 Pro。
- **Pro 专注推理**：规划、审查、复杂实现只走 Pro。

用 `/model` 切换，或直接改 `settings.json` 的 `modelName`。

## 核心原则

1. **意图优先**：字面请求 ≠ 真实目标。「看一下 X」「解释 X」不是「改 X」。未明确要求实现时，不要直接改文件。
2. **最小改动**：做能完整解决问题的最少修改。完整正确 > 宽泛聪明。不碰无关代码。
3. **读前不猜**：不猜代码行为——打开它，用真实文件验证假设。
4. **独立并行**：多个不依赖的读取 / 搜索 / 检索一次性发起，不串行。
5. **不主动创建文件**：未经明确请求，不创建 README、文档或任何新文件。
6. **停止条件明确**：动手前在心中定义「完成」的可观测条件。一旦达到且已验证，立即停止——不加多余润色、不额外重构。
7. **语言跟随 OS**：zh-CN 系统用中文回复，en-US 系统用英文回复。

## 约束

- **不引入新模型**。仅使用 `deepseek-v4-flash` 与 `deepseek-v4-pro`。
- **不擅自新增依赖**，除非明确说明理由且经确认。
- **纯配置优先**。优先改提示词 / 配置，而非引入新工具。

## 多步任务纪律

任何 ≥2 步的任务：
1. 先写有序待办清单。
2. 同一时刻只保留一个「进行中」。
3. 每完成一项立即标记完成，不批量处理。
4. 范围变化时更新清单。

## 上下文与 Token 效率

- **引用路径，不贴整文件**：指向 `src/app.ts:42`，不把整个文件塞入提示词。
- **委派而非堆积**：大文件交由子代理读取，不灌入主上下文。
- **积极压缩**：一条线索结论清晰后立即压缩上下文，从干净状态开始实现。
- **快变库先检索**：具体或高频变动的库/API 不凭记忆写，先查官方文档。

## 何时提问 vs 直接执行

仅在「存在多种影响差异大的解释」或「关键上下文缺失」时提问。否则选最佳默认值，说明假设后继续。

## 反模式（阻断）

- 不建 `utils.ts` / `helpers.ts` / `service.ts` 等万能文件——用描述性文件名。
- 代码/注释中不用 emoji（除非明确要求）。
- 不用「simply」「obviously」「clearly」等 AI 填充词。
- 不留空 `catch` 块；如确实可忽略，必须注释说明原因。
- `@ts-ignore` / `@ts-expect-error` 必须附解释性注释，说明原因及可移除条件。
- 不留被注释掉的死代码——git 历史才是去处。
- 未经请求不创建文件。

## 代码风格

- 优先 `const`，非必要不用 `let`。用三元表达式或提前返回代替重赋值。
- 能不用 `else` 就不用——用提前返回压平结构。
- 数据变换优先函数式（`map` / `filter` / `flatMap`）而非命令式 `for`。
- 只用一次的值就地内联，减少中间变量。
- 不用的解构、别名、通配符导入一律省略。
- 不提前提取只用一次的辅助函数——分散逻辑而不增加清晰度。

## 注释纪律

- 注释解释 WHY，不解释 WHAT。如果读代码就能看出做了什么，删掉注释。
- 不写 AI 样板注释。
- 匹配项目既有注释风格；如果项目不用 docstring，不加。

## 证据纪律

完成前必须有可验证证据——不允许没有证据就声称完成：

- 测试通过：实际运行测试命令并确认输出。
- 构建成功：实际运行构建命令并确认退出码为 0。
- 调用方完整：grep 确认修改的函数/类型没有残留的破损调用。
- 无未用导入：检查所有修改文件。

**在 claim 任何完成状态之前，先产生证据。** 不依赖「应该没问题」「看起来对」等推断。

## 自检清单（提交前）

1. 复读每个改动文件，端到端确认无遗留的调试输出、TODO、不完整逻辑。
2. grep 确认修改的函数/类型的所有调用方未被破坏。
3. 有测试则运行；如无，明确说明测试不可用。
4. 检查每个修改文件无未用导入/变量/参数。

## SubCommand 使用

本项目预置了 4 个 SubCommand（`.iflow/commands/`），用 `/command` 调用：

| 命令 | 用途 |
| --- | --- |
| `code-review` | 五维度代码审查（正确性、安全、性能、架构、可维护性） |
| `conventional-commits` | 按 Conventional Commits 规范生成提交信息 |
| `security-review` | 安全漏洞审查（注入、XSS、SSRF、密钥泄露等） |
| `verify` | 完成前验证——运行验证命令、确认输出、产生证据 |
