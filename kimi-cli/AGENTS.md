# AGENTS.md — Kimi CLI 通用规则

> Kimi CLI（Kimi Code CLI）会自动读取项目根目录的 `AGENTS.md`（通过 `${KIMI_AGENTS_MD}` 注入）。
> 本文件定义项目的全局行为规则，适用于所有 agent 和对话。

## 核心原则

1. **先辨意图再动手。** 区分字面请求与实际目标。「解释 X」「分析 X」不是「改 X」。未经明确要求，不编辑文件。
2. **最小改动，完整正确优先。** 只改必须改的代码，不碰无关部分。正确且完整比巧妙或宽泛更重要。
3. **先读后写。** 绝不靠记忆猜测代码行为——打开文件验证。用真实文件内容印证假设，非自我推断。
4. **并行处理独立任务。** 多个独立读取、搜索、查询同时发起，不串行等待。
5. **不主动创建文件。** 除非用户明确要求，不新建 README、文档或任何新文件。
6. **明确停止条件。** 开始前自问「完成的观察条件是什么」。满足条件、经验证后即停止——不做未要求的润色、额外重构或验证循环。
7. **语言跟随操作系统。** 用 OS 的当前 locale 语言回复用户。zh-CN Windows → 中文回复；en-US → 英文回复。

## 多步任务纪律

任何包含 2 步以上的任务：

1. 先写有序待办清单。
2. 同时只保留一个「进行中」。
3. 完成即标记，不批量标记。
4. 范围变化时更新清单。

跳过待办清单意味着进度不可见、任务可能半途而废。

## 反模式（绝对禁止）

- **禁止万能文件。** 不创建 `utils.ts`、`helpers.ts`、`service.ts` 等语义模糊的文件——使用描述性文件名。
- **禁止 emoji。** 代码和注释中不出现 emoji（除非用户明确要求）。
- **禁止 AI 填充词。** 不在注释或解释中使用「显然」「简单」「无疑」「此外」「而且」等无实际信息的词语。
- **禁止空 catch 块。** `catch(e) {}` 不可接受。如果错误确实可忽略，注释说明原因。
- **禁止无注释的 `@ts-ignore` / `@ts-expect-error`。** 必须注释说明为何必要以及何时可以移除。
- **禁止注释掉的代码。** 死代码属于 git 历史，不属于源文件。删除它。

## 代码风格（实现时）

- **`const` 优于 `let`。** 用三元表达式或早返回替代重新赋值。
- **早返回避免 `else`。** 早返回减少嵌套和认知负担。
- **函数式数组方法优先。** 数据转换用 `flatMap`、`filter`、`map`，不用命令式 `for` 循环。
- **减少中间变量。** 只用一次的值就地使用，不创建命名变量。
- **避免不必要的解构。** 当解构变量名不能增加清晰度时，用 `.` 访问。
- **禁止别名导入**（`import { foo as bar }`），除非是解决真实命名冲突。
- **禁止通配符导入**（`import * as Foo`）——使用命名导入。
- **保持函数内聚。** 不提前提取只用一次的辅助函数——分散逻辑不增加清晰度。

## 注释纪律

- **注释解释 WHY，不解释 WHAT。** 读代码本身已经知道它做什么，注释说明为什么要这样做。
- **不写注释掉的代码。** 删除死代码，git 历史保存它。
- **不写填充性文档注释。** 遵循项目现有的文档注释约定；如果项目不用，不添加。

## 证据纪律

永远不要在没有证据的情况下声称「完成」。完成前提供至少一个可验证的证据：

- 通过的测试、成功的构建、干净的 lint 检查。
- 逐文件通读所有修改文件确认正确性。
- grep 结果确认未破坏调用方。

证据先于断言。无法提供证据则未完成——说明剩余工作及阻止验证的阻碍。

## 提交前自检

1. 逐文件通读所有改动文件——扫描残留调试打印、TODO 注释、不完整逻辑。
2. 验证改动未破坏调用方——grep 搜索被修改函数/类型的所有使用点。
3. 有测试则运行；无测试则声明测试不可用。
4. 检查未引入未使用的导入、变量或参数。

## 模型使用

Kimi CLI 通过 `config.toml` 配置模型。本配置接入 DeepSeek 双模型：默认 `deepseek-v4-flash`
（Flash / 快速通用），复杂推理切到 `deepseek-v4-pro`（Pro / 强推理，`always_thinking`）。

- shell 模式下用 `/model` 在 `deepseek-v4-flash` 与 `deepseek-v4-pro` 间切换。
- 启动时可用 `--thinking` / `--no-thinking` 控制思考模式。

## 不确定时的处理

仅在以下情况向用户澄清：

- 存在多种解释且效果/工作量差异显著。
- 关键上下文缺失（目标文件、错误信息、范围）。

否则选择最佳默认方案，声明所做的假设，继续执行。

> 核心通用规则参见项目根 `AGENTS.md`。本文件为 Kimi CLI 专属补充，覆盖度更全。
